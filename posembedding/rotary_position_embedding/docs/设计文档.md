# RotaryPositionEmbedding 算子设计文档

---

## 一、需求分析

### 1.1 需求背景

旋转位置编码（Rotary Position Embedding，简称 RoPE）是 Transformer 模型中用于注入位置信息的关键技术，最早由 RoFormer 论文提出。相较于传统的正弦位置编码，RoPE 通过旋转矩阵的方式编码位置信息，能够更好地捕获相对位置关系，在长序列建模和相对位置感知方面表现更优。

在当前的大模型（如 GPT、LLaMA、Qwen 等）中，RoPE 已成为标配技术，广泛应用于注意力计算中的 Query 和 Key 向量位置编码。

### 1.2 功能分析

本算子实现单路旋转位置编码计算，支持多种数据类型和计算模式，主要功能包括：

**核心功能：**
1. 对输入张量执行旋转位置编码计算
2. 支持多种旋转模式（half、interleave、quarter、interleave-half）
3. 支持多种数据类型（FLOAT32、FLOAT16、BFLOAT16）
4. 支持动态形状和动态秩
5. 支持输入张量广播

**计算公式：**

针对不同的硬件平台和模式，实现不同的旋转策略：

**Atlas A2/A3（membase 架构）：**

1. **Half 模式（mode=0）**：
   - 将输入张量按最后一维前半和后半切分
   - 将后半部分取负后与前半部分拼接
   - 执行旋转计算：`y = x * cos + x_rotate * sin`

   ```
   x1 = x[..., : x.shape[-1] // 2]
   x2 = x[..., x.shape[-1] // 2 :]
   x_rotate = torch.cat((-x2, x1), dim=-1)
   y = x * cos + x_rotate * sin
   ```

2. **Interleave 模式（mode=1）**：
   - 将输入张量按奇偶位切分
   - 将偶数位取负后与奇数位交叉拼接
   - 执行旋转计算

   ```
   x1 = x[..., ::2]
   x2 = x[..., 1::2]
   x_rotate = torch.cat((-x2, x1), dim=-1).view(x.shape)
   y = x * cos + x_rotate * sin
   ```

**Ascend 950PR（regbase 架构）：**

3. **Quarter 模式（mode=2）**：
   - 将输入张量按最后一维四等分
   - 第二部分和第四部分取负，按特定顺序拼接
   - 执行旋转计算

   ```
   x1 = x[..., : D//4]
   x2 = x[..., D//4 : D//2]
   x3 = x[..., D//2 : D*3//4]
   x4 = x[..., D*3//4 :]
   x_rotate = torch.cat((-x2, x1, -x4, x3), dim=-1)
   y = x * cos + x_rotate * sin
   ```

4. **Interleave-half 模式（mode=3）**：
   - 先按奇偶位抽取，分别拼接成前半和后半部分
   - 对后半部分取负
   - 执行旋转计算

   ```
   x1 = x[..., ::2]
   x2 = x[..., 1::2]
   x_part1 = torch.cat((x1, x2), dim=-1)
   x_part2 = torch.cat((-x2, x1), dim=-1)
   y = x_part1 * cos + x_part2 * sin
   ```

### 1.3 对标实现分析

**PyTorch 参考实现（HuggingFace）：**
- PyTorch 通过 `torch.matmul` 和逐元素乘积实现
- 使用 `torch.cos` 和 `torch.sin` 预计算位置编码
- 通过张量切片和拼接实现不同的旋转模式

**竞品实现特点：**
1. CPU/GPU 上的实现较为简单，主要依赖张量操作
2. NPU 实现需要考虑：
   - 片上内存（UB）容量限制
   - AI Core 并行计算能力
   - 数据布局优化（连续性、对齐）
   - 多种数据类型的精度处理
   - 不同硬件架构的指令集差异

**本算子优势：**
1. 高性能：针对 Ascend NPU 优化，充分利用 AI Core 计算能力
2. 灵活性：支持多种旋转模式，适应不同模型需求
3. 确定性：保证计算结果的确定性
4. 动态支持：支持动态形状和动态秩

## 二、特性实现方案

### 2.1 算子整体计算流程图

```
                    ┌─────────────────┐
                    │  输入张量 x    │
                    │  (B, N, S, D)   │
                    └────────┬────────┘
                             │
                    ┌────────▼────────┐
                    │ Infershape 推断 │
                    │ 输出形状 = x   │
                    └────────┬────────┘
                             │
                    ┌────────▼────────┐
                    │  Tiling 分片策略│
                    │ 根据 mode、dtype│
                    │ shape、硬件配置│
                    └────────┬────────┘
                             │
                    ┌────────▼────────┐
                    │ Kernel 计算核心 │

                    │  - CopyOut: UB→GM│
                    └────────┬────────┘

                    ┌────────▼────────┐
                    │  输出张量 y    │
                    │  (B, N, S, D)   │
                    └─────────────────┘
```

### 2.2 aclnn 设计

**接口定义：**

算子采用两段式 aclnn 接口设计：

```cpp
// 第一段：获取 workspace 大小和 executor
aclnnStatus aclnnRotaryPositionEmbeddingGetWorkspaceSize(
    const aclTensor *x,
    const aclTensor *cos,
    const aclTensor *sin,
    int64_t mode,
    aclTensor *out,
    uint64_t *workspaceSize,
    aclOpExecutor **executor
);

// 第二段：执行计算
aclnnStatus aclnnRotaryPositionEmbedding(
    void *workspace,
    uint64_t workspaceSize,
    aclOpExecutor *executor,
    aclrtStream stream
);
```

**接口设计要点：**
1. **输入参数**：
   - `x`：待旋转的张量，支持 FLOAT16、FLOAT32、BFLOAT16
   - `cos`：位置编码余弦值，与 x 数据类型一致
   - `sin`：位置编码正弦值，与 x 数据类型一致
   - `mode`：旋转模式，支持 0/1/2/3
   - `out`：输出张量，形状与 x 相同

2. **输出参数**：
   - `workspaceSize`：需要的 workspace 大小
   - `executor`：算子执行器

3. **执行参数**：
   - `workspace`：Device 侧 workspace 地址
   - `workspaceSize`：workspace 大小
   - `stream`：执行流

4. **错误处理**：
   - ACLNN_ERR_PARAM_NULLPTR（161001）：输入参数为空
   - ACLNN_ERR_PARAM_INVALID（161002）：参数类型/格式不支持
   - ACLNN_ERR_INNER_TILING_ERROR（561002）：shape 不匹配或 mode 参数无效

### 2.3 Infershape 设计

**推断逻辑：**

```cpp
ge::graphStatus InferShapeForRotaryPositionEmbedding(gert::InferShapeContext *context)
{
    // 获取输入形状
    const gert::Shape *xShape = context->GetInputShape(INPUT_X_INDEX);
    const gert::Shape *cosShape = context->GetInputShape(INPUT_COS_INDEX);
    const gert::Shape *sinShape = context->GetInputShape(INPUT_SIN_INDEX);
    const gert::Shape *yShape = context->GetOutputShape(OUTPUT_Y_INDEX);

    // 输出形状等于输入 x 的形状
    *yShape = *xShape;

    return ge::GRAPH_SUCCESS;
}
```

**设计要点：**
1. **输出形状**：直接复制输入 x 的形状，因为旋转操作不改变张量形状
2. **数据类型**：输出数据类型与输入 x 保持一致
3. **动态形状**：支持动态形状，输出形状随输入形状变化
4. **广播校验**：在 Tiling 阶段校验 cos/sin 与 x 的广播关系

### 2.4 Tiling 设计

**Tiling 策略注册：**

```cpp
// 注册两种 Tiling 策略
REGISTER_OPS_TILING_TEMPLATE(RotaryPositionEmbedding, RopeRotateHalfTilingClass, 50000);  // half 模式
REGISTER_OPS_TILING_TEMPLATE(RotaryPositionEmbedding, RopeInterLeavedTilingClass, 60000);  // interleave 模式
```

**Tiling 数据结构：**

```cpp
struct RotaryPositionEmbeddingTilingData {
    uint32_t totalLength;          // 总元素数量
    uint32_t blockLength;          // 每个 block 处理的元素数
    uint32_t tileNum;             // 每个 block 的 tile 数量
    uint32_t tileLength;          // 每个 tile 的长度
    uint32_t halfDim;            // 旋转维度的一半
    uint32_t mode;               // 旋转模式
    uint32_t dtypeSize;          // 数据类型大小
    // ... 其他配置参数
};
```

**Tiling Key 设计：**

| Tiling Key | 数据类型 | 计算模式 | 场景说明 |
|------------|----------|-----------|----------|
| 1011 | float32 | half | Atlas A2/A3 基础场景 |
| 1012 | float16 | half | Atlas A2/A3 半精度场景 |
| 1013 | bfloat16 | half | Atlas A2/A3 BF16 场景 |
| 2000 | float16 | interleave | Atlas A2/A3 interleave 模式 S 切分 |
| 2100 | float16 | interleave | Atlas A2/A3 interleave 模式 BS 切分 |
| 2200 | float16 | interleave | Atlas A2/A3 interleave 模式 BSN 切分 |

**Tiling 分片策略：**

1. **Half 模式 Tiling（RopeRotateHalfTilingClass）**：
   - 根据 `B * N` 的大小选择不同的切分策略
   - 小场景（`B * N < 1000`）：直接按 B 维度切分
   - 大场景：考虑 D 维度的对齐和 UB 利用率

2. **Interleave 模式 Tiling（RopeInterLeavedTilingClass）**：
   - 根据 cos/sin 的形状选择切分策略
   - 支持 11SD、B1SD、BNSD、1S1D、BSND、S11D 等多种广播场景
   - 每种场景对应不同的 Kernel 实现

**Tiling 关键参数计算：**

```cpp
// 获取平台信息
aicoreParams_.numBlocks = ascendcPlatform.GetCoreNumAiv();
ascendcPlatform.GetCoreMemSize(platform_ascendc::CoreMemType::UB, ubSizePlatForm);

// 计算 block 长度
blockLength_ = (totalLength + aicoreParams_.numBlocks - 1) / aicoreParams_.numBlocks;

// 计算 tile 长度（考虑 UB 容量）
tileLength_ = blockLength_ / tileNum_ / BUFFER_NUM;

// 计算旋转维度
halfDim_ = D / 2;
```

**Tiling 约束校验：**
1. D 维度约束：`D < 896`（A2/A3）或 `D <= 1024`（950PR）
2. 对齐约束：`D % 2 == 0`（half/interleave）或 `D % 4 == 0`（quarter）
3. 广播约束：cos/sin 广播后 shape 必须等于 x 的 shape
4. 数量约束：`B < 1000`、`N < 1000` 等

### 2.5 片上内存资源设计

**内存层次结构：**

```
┌─────────────────────────────────────────┐
│         Global Memory (GM)            │
│  - 输入张量 x、cos、sin             │
│  - 输出张量 y                     │
│  - 容量大，访问延迟高               │
└─────────────────┬───────────────────┘
                  │ DataCopy
┌─────────────────▼───────────────────┐
│      Unified Buffer (UB)            │
│  - 片上高速缓存                       │
│  - 容量有限（~256KB）               │
│  - 双缓冲（BUFFER_NUM=2）           │
└─────────────────┬───────────────────┘
                  │ Compute
┌─────────────────▼───────────────────┐
│         AI Core                     │
│  - 向量计算单元 (Vector)              │
│  - 立方计算单元 (Cube)               │
│  - 并行执行                           │
└───────────────────────────────────┘
```

**双缓冲设计：**

```cpp
constexpr int32_t BUFFER_NUM = 2;

class RotaryPositionEmbedding {
    TPipe pipe;
    TQue<QuePosition::VECIN, BUFFER_NUM> inputQueueX;
    TQue<QuePosition::VECIN, BUFFER_NUM> inputQueueCos;
    TQue<QuePosition::VECIN, BUFFER_NUM> inputQueueSin;
    TQue<QuePosition::VECOUT, BUFFER_NUM> outputQueueY;
};
```

**内存分配策略：**

1. **输入缓冲区**：
   - `inputQueueX`：存储输入 x 的数据块
   - `inputQueueCos`：存储 cos 的数据块（广播数据）
   - `inputQueueSin`：存储 sin 的数据块（广播数据）

2. **输出缓冲区**：
   - `outputQueueY`：存储计算结果

3. **容量计算**：
   ```cpp
   // 计算每个 buffer 的容量
   uint32_t xBufferSize = tileLength_ * sizeof(T);
   uint32_t cosSinBufferSize = halfDim_ * sizeof(T);
   uint32_t yBufferSize = tileLength_ * sizeof(T);

   // 初始化 pipe 和 queues
   pipe.InitBuffer(inputQueueX, BUFFER_NUM, xBufferSize);
   pipe.InitBuffer(inputQueueCos, BUFFER_NUM, cosSinBufferSize);
   pipe.InitBuffer(inputQueueSin, BUFFER_NUM, cosSinBufferSize);
   pipe.InitBuffer(outputQueueY, BUFFER_NUM, yBufferSize);
   ```

**内存优化策略：**
1. **广播数据复用**：cos 和 sin 通常在多个维度上广播，只加载需要的部分
2. **对齐访问**：确保数据访问地址对齐，提升访存效率
3. **数据重用**：在 UB 中尽可能复用数据，减少 GM 访问

if (TILING_KEY_IS(1011) || TILING_KEY_IS(1012) || ...) {

**Kernel 类模板设计：**

```cpp
template <typename T>
class RotateHalf {
public:
    __aicore__ inline void Init(GM_ADDR x, GM_ADDR cos, GM_ADDR sin,
                               GM_ADDR y, const RotaryPositionEmbeddingTilingData* tiling);
    __aicore__ inline void Process();

private:
    __aicore__ inline void CopyIn(int32_t progress);
    __aicore__ inline void Compute(int32_t progress);
    __aicore__ inline void CopyOut(int32_t progress);

private:
    GlobalTensor<T> inputGMX;
    GlobalTensor<T> inputGMCos;
    GlobalTensor<T> inputGMSin;
    GlobalTensor<T> outputGMY;

    TQue<QuePosition::VECIN, BUFFER_NUM> inputQueueX;
    TQue<QuePosition::VECIN, BUFFER_NUM> inputQueueCos;
    TQue<QuePosition::VECIN, BUFFER_NUM> inputQueueSin;
    TQue<QuePosition::VECOUT, BUFFER_NUM> outputQueueY;

    uint32_t halfDim_;
    uint32_t tileLength_;
};
```

**计算流程：**

```cpp
template <typename T>
__aicore__ inline void RotateHalf<T>::Process()
{
    for (int32_t i = 0; i < tileNum_; i++) {
        CopyIn(i);
        Compute(i);
        CopyOut(i);
    }
}

template <typename T>
__aicore__ inline void RotateHalf<T>::Compute(int32_t progress)
{
    LocalTensor<T> xLocal = inputQueueX.DeQue<T>();
    LocalTensor<T> cosLocal = inputQueueCos.DeQue<T>();
    LocalTensor<T> sinLocal = inputQueueSin.DeQue<T>();
    LocalTensor<T> yLocal = outputQueueY.AllocTensor<T>();

    // Half 模式旋转计算
    // x1 = x[0:halfDim], x2 = x[halfDim:D]
    // x_rotate = concat(-x2, x1)
    // y = x * cos + x_rotate * sin

    LocalTensor<T> x1 = xLocal[0];
    LocalTensor<T> x2 = xLocal[halfDim_];

    // 旋转部分：-x2 拼接 x1
    LocalTensor<T> xRotate = outputQueueY.AllocTensor<T>();
    Duplicate(xRotate, x2, halfDim_);
    Muls(xRotate, xRotate, -1.0f, halfDim_);

    // 执行旋转公式：y = x * cos + x_rotate * sin
    Muls(yLocal, xLocal, cosLocal, tileLength_);
    Muls(xRotate, xRotate, sinLocal, tileLength_);
    Adds(yLocal, yLocal, xRotate, tileLength_);

    outputQueueY.EnQue<T>(yLocal);
    inputQueueX.FreeTensor(xLocal);
    inputQueueCos.FreeTensor(cosLocal);
    inputQueueSin.FreeTensor(sinLocal);
}
```

**不同模式的 Kernel 实现：**

1. **Half 模式 Kernel**（`rotate_half.h`）：
   - 使用 `Duplicate`、`Muls`、`Adds` 等基础算子
   - 支持多种数据类型：`RotateHalf<float>`、`RotateHalfBf16<half, float>`、`RotateHalfBf16<bfloat16_t, float>`

2. **Interleave 模式 Kernel**（`rotate_interleaved_split_*.h`）：
   - 根据 cos/sin 的形状选择不同的切分策略：
     - `InterleavedSplitS`：S 维度切分（11SD 形状）
     - `InterleavedSplitBS`：BS 维度切分（11SD 形状）
     - `InterleavedSplitBSN`：BSN 维度切分（11SD 形状）
   - 使用双缓冲和流水线优化

3. **Ascend 950PR 专用 Kernel**（`arch35/`）：
   - 实现 quarter 和 interleave-half 模式
   - 使用 regbase 特定的指令和优化策略
   - 文件：`rotary_position_embedding_a_and_b.h`、`rotary_position_embedding_bab.h`、`rotary_position_embedding_aba_and_ba.h`、`rotary_position_embedding_ab.h`

**指令优化：**
1. **向量化计算**：使用 AscendC 的向量指令并行计算
2. **指令融合**：融合多个操作减少中间结果存储
3. **数据重排**：优化数据布局以匹配硬件访问模式
4. **条件分支优化**：使用编译时常量减少运行时分支

## 五、遗留问题

### 5.1 已知限制

1. **D 维度上限**：
   - Atlas A2/A3：D < 896
   - Ascend 950PR：D <= 1024
   - **原因**：受 UB 容量限制
   - **影响**：超大 embedding 维度的模型需要分段处理

2. **Batch/N 维度限制**：
   - Half 模式：B < 1000, N < 1000
   - Interleave 模式：B * N < 1000
   - **原因**：Tiling 策略的限制
   - **影响**：超大 batch 场景性能下降

3. **广播场景限制**：
   - Interleave 模式只支持部分广播场景
   - **原因**：Kernel 实现复杂度
   - **影响**：某些广播场景需要回退到其他模式

### 5.2 性能优化方向

1. **Quarter 模式优化**：
   - 当前仅支持 Ascend 950PR
   - **优化方向**：扩展到 Atlas A2/A3

2. **Interleave-half 模式优化**：
   - 当前仅支持 Ascend 950PR
   - **优化方向**：扩展到 Atlas A2/A3

3. **Tiling 策略优化**：
   - 当前针对特定场景的 Tiling 策略
   - **优化方向**：自适应 Tiling，根据输入自动选择最优策略

4. **指令融合优化**：
   - 当前使用基础算子组合
   - **优化方向**：使用融合指令减少中间结果

### 5.3 功能扩展方向

1. **多路旋转**：
   - 当前仅支持单路旋转
   - **扩展方向**：支持多路输入并行旋转

2. **自定义旋转角度**：
   - 当前使用预计算的 cos/sin
   - **扩展方向**：支持输入角度参数，内部计算 cos/sin

3. **稀疏模式支持**：
   - 当前仅支持稠密张量
   - **扩展方向**：支持稀疏张量的旋转

### 5.4 兼容性问题

1. **Kirin 平台 BF16 支持**：
   - Kirin X90/9030 不支持 BF16
   - **解决方案**：在 `rotary_position_embedding_def.cpp` 中通过条件编译排除

2. **旧架构支持**：
   - Atlas 200I/500 A2 不支持
   - **原因**：架构指令集不兼容
   - **解决方案**：用户升级到支持的产品
