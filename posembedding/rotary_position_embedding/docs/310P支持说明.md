# RotaryPositionEmbedding 算子 310P 芯片支持说明

## 概述

本文档说明为 RotaryPositionEmbedding 算子在 310P 芯片（Atlas 推理系列产品）上实现支持所做的修改。

## 需求

- **芯片**：310P（Atlas 推理系列产品，架构 arch20）
- **支持的模式**：mode=0（half 模式）
- **支持的 D 值**：32, 64, 96, 128
- **支持的数据类型**：FP16, FP32（不支持 BF16）
- **指令限制**：310P 不支持 DataCopyPad 指令

1. **posembedding/rotary_position_embedding/op_host/rotary_position_embedding_def.cpp**

bool IsCapable() override
{
    if ((socVersion_ == platform_ascendc::SocVersion::ASCEND910B ||
         socVersion_ == platform_ascendc::SocVersion::KIRINX90 ||
         socVersion_ == platform_ascendc::SocVersion::KIRIN9030) && inputMode_ != MODE_ROTATE_INTERLEAVED) {

#### 4.5 实现 310P 专用搬运函数

在文件末尾添加三个专用函数：

##### CopyInR_310P
```cpp
template <typename T>
__aicore__ inline void RotateHalf<T>::CopyInR_310P(uint64_t rStartOffset, uint16_t sLines, uint32_t copyLength)
{
    LocalTensor<T> cosLocal = inQueueCos.AllocTensor<T>();
    LocalTensor<T> sinLocal = inQueueSin.AllocTensor<T>();
    // 使用简单的 DataCopy，不使用 DataCopyPad
    DataCopy(cosLocal, cosGm[rStartOffset], copyLength);
    DataCopy(sinLocal, sinGm[rStartOffset], copyLength);
    inQueueCos.EnQue(cosLocal);
    inQueueSin.EnQue(sinLocal);
}
```

##### CopyInX_310P
```cpp
template <typename T>
__aicore__ inline void RotateHalf<T>::CopyInX_310P(uint64_t xStartOffset, uint16_t sLines, uint32_t copyLength)
{
    LocalTensor<T> xLocal = inQueueX.AllocTensor<T>();
    if (this->layout == LAYOUT_BNSD || this->layout == LAYOUT_NO_BROADCAST ||
        this->layout == LAYOUT_BND || this->layout == LAYOUT_R_B1SD) {
        // 直接复制
        DataCopy(xLocal, xGm[xStartOffset], copyLength);
    } else if (this->layout == LAYOUT_BSND) {
        // BSND 布局：循环逐行复制处理 stride
        for (uint16_t i = 0; i < sLines; i++) {
            uint64_t lineOffset = i * this->bcSecondDim * this->dLength;
            for (uint32_t j = 0; j < this->bcSecondDim; j++) {
                DataCopy(xLocal[lineOffset + j * this->dLength],
                         xGm[xStartOffset + i * this->dLength + j * this->bcSecondDim * this->dLength],
                         this->dLength);
            }
        }
    } else if (this->layout == LAYOUT_SBND) {
        // SBND 布局：循环逐行复制处理 stride
        for (uint16_t i = 0; i < sLines; i++) {
            uint64_t lineOffset = i * this->bnSize * this->dLength;
            for (uint32_t j = 0; j < this->bnSize; j++) {
                DataCopy(xLocal[lineOffset + j * this->dLength],
                         xGm[xStartOffset + i * this->dLength + j * this->bnSize * this->dLength],
                         this->dLength);
            }
        }
    }
    inQueueX.EnQue(xLocal);
}
```

##### CopyOut_310P
```cpp
template <typename T>
__aicore__ inline void RotateHalf<T>::CopyOut_310P(uint64_t yStartOffset, uint16_t sLines, uint32_t copyLength)
{
    LocalTensor<T> yLocal = outQueueY.DeQue<T>();
    if (this->layout == LAYOUT_BNSD || this->layout == LAYOUT_NO_BROADCAST ||
        this->layout == LAYOUT_BND || this->layout == LAYOUT_R_B1SD) {
        // 直接复制
        DataCopy(yGm[yStartOffset], yLocal, copyLength);
    } else if (this->layout == LAYOUT_BSND) {
        // BSND 布局：循环逐行复制处理 stride
        for (uint16_t i = 0; i < sLines; i++) {
            uint64_t lineOffset = i * this->bcSecondDim * this->dLength;
            for (uint32_t j = 0; j < this->bcSecondDim; j++) {
                DataCopy(yGm[yStartOffset + i * this->dLength + j * this->bcSecondDim * this->dLength],
                         yLocal[lineOffset + j * this->dLength],
                         this->dLength);
            }
        }
    } else if (this->layout == LAYOUT_SBND) {
        // SBND 布局：循环逐行复制处理 stride
        for (uint16_t i = 0; i < sLines; i++) {
            uint64_t lineOffset = i * this->bnSize * this->dLength;
            for (uint32_t j = 0; j < this->bnSize; j++) {
                DataCopy(yGm[yStartOffset + i * this->dLength + j * this->bnSize * this->dLength],
                         yLocal[lineOffset + j * this->dLength],
                         this->dLength);
            }
        }
    }
    outQueueY.FreeTensor(yLocal);
}
```

#### 关键点
- 使用 `__NPU_ARCH__ == 3003 || __NPU_ARCH__ == 3113` 宏来识别 310P 芯片
- 310P 的 D 值（32, 64, 96, 128）都是对齐的，所以 `isAligned` 总是 true
- 不使用 `DataCopyPad` 指令，改用 `DataCopy` 或循环逐行复制
- 对于需要处理 stride 的布局（BSND, SBND），使用循环逐行复制的方式
- 编译时通过宏隔离，不会编译到 310P 不支持的代码

## 技术要点总结

### 1. 芯片识别
- **310P 架构标识**：`__NPU_ARCH__ == 3003 || __NPU_ARCH__ == 3113`
- **运行时识别**：`platform_ascendc::SocVersion::ASCEND310P`
- **对应目录**：arch20

### 2. 数据类型限制
- **支持**：FP16, FP32
- **不支持**：BF16

### 3. D 值限制
- **支持**：32, 64, 96, 128
- **对齐性**：这些值都能被 32 整除，满足 32 字节块对齐要求
- **拦截位置**：tiling 阶段的 `CheckShapeSupport()` 函数

### 4. Mode 限制
- **支持**：mode=0（MODE_ROTATE_HALF，half 模式）
- **不支持**：mode=1（MODE_ROTATE_INTERLEAVED，interleaved 模式）
- **拦截位置**：tiling 阶段的 `IsCapable()` 函数

### 5. 指令差异
- **310P 不支持**：`DataCopyPad` 指令
- **替代方案**：使用 `DataCopy` 或循环逐行复制

### 6. 编译时隔离
- 使用预编译宏 `#if (defined(__NPU_ARCH__) && (__NPU_ARCH__ == 3003 || __NPU_ARCH__ == 3113))`
- 在编译阶段就隔离了不同芯片的代码
- 不会在 310P 上编译包含 `DataCopyPad` 的代码路径

### 7. 代码复用
- 310P 和 Kirin 的配置相同（都只支持 FP16/FP32）
- 复用 `GetFP16FP32CoreConfig()` 函数
- 避免代码重复

## Layout 类型说明

算子根据输入 shape 的广播情况选择不同的 layout：

| Layout 常量 | 值 | 说明 |
|-------------|-----|------|
| LAYOUT_BNSD | 1 | Batch-Num-Seq-Dim 布局 |
| LAYOUT_BSND | 2 | Batch-Seq-Num-Dim 布局 |
| LAYOUT_SBND | 3 | Seq-Batch-Num-Dim 布局 |
| LAYOUT_NO_BROADCAST | 4 | 无广播模式（x = r） |
| LAYOUT_BND | 5 | Batch-Num-Dim 布局（S=1） |
| LAYOUT_R_B1SD | 6 | r 为 B1SD 布局 |

对于非连续布局（BSND, SBND），310P 使用循环逐行复制来处理 stride。

## 注意事项

1. **编译环境**：确保已配置好 CANN 开发环境和 ascend310p 编译器
2. **性能考虑**：对于 BSND/SBND 布局，循环逐行复制可能性能略低，但由于 D 值较小（最大 128），影响有限
3. **内存对齐**：由于 D 值都是 32 的倍数，内存访问都是对齐的，不会影响性能
4. **向后兼容**：修改不影响其他芯片（910B, 910_93, 950, Kirin）的功能
