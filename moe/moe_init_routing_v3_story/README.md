## 1. 引言

### 1.1 算子概述

`MoeInitRoutingV3` 是 MoE (Mixture of Experts) 模型的路由初始化算子，核心功能是将 token 按专家 ID 排序并重排特征数据，为后续专家计算做准备。

该算子广泛应用于主流 MoE 模型：

| 模型 | 专家数 | Top-K |
|------|--------|-------|
| Mixtral-8x7B | 8 | 2 |
| DeepSeek-V2 | 160 | 6 |
| Qwen-MoE | 60 | 4 |

### 1.2 MoE 推理流程

```
输入 Token (N, H)
       │
       ▼
┌──────────────┐
│    Router    │────▶ expertIdx (N, K): 每个 token 选中的专家 ID
└──────────────┘
       │
       ▼
┌─────────────────────────────────────────────────────┐
│            MoeInitRoutingV3（本算子）                 │
│                                                     │
│  功能：按专家排序 token，重排特征数据                  │
│  输入：x (N, H), expertIdx (N, K)                   │
│  输出：expandedXOut, expandedRowIdxOut, tokenCount  │
└─────────────────────────────────────────────────────┘
       │
       ▼
┌──────────────┐
│   Experts    │  每个专家独立处理分配到的 token
└──────────────┘
```

### 1.3 计算流程

**输入输出定义：**
```
输入:
  x:          Token 特征，shape (N, H)，如 (1024, 4096)
  expertIdx:  选中专家 ID，shape (N, K)，如 (1024, 8)

输出:
  expandedXOut:          重排后特征，shape (N*K, H)
  expandedRowIdxOut:     索引映射，shape (N*K,)
  expertTokensCountOut:  每个专家处理的 token 数量
```

**Step 1: 排序**

按 expertIdx 排序，将相同专家的 token 放在一起：

```
示例 (N=4, K=2):

expertIdx:    [[1,3], [0,2], [1,2], [0,3]]
                ↓ 展开
flat:         [1, 3, 0, 2, 1, 2, 0, 3]
rowIdx:       [0, 0, 1, 1, 2, 2, 3, 3]
                ↓ 排序
sortedExpert: [0, 0, 1, 1, 2, 2, 3, 3]  ← 按专家ID排序
sortedRowIdx: [1, 3, 0, 2, 1, 2, 0, 3]  ← 原始token位置
```

**Step 2: 索引映射**

建立输出位置与输入位置的映射关系：

```
Scatter 模式: expandedRowIdxOut[i] = sortedRowIdx[i]
Gather 模式:  expandedRowIdxOut[sortedRowIdx[i]] = i
```

**Step 3: 直方图统计**

统计每个专家处理的 token 数量：

```
sortedExpert: [0, 0, 1, 1, 2, 2, 3, 3]
                ↓ 统计
expertTokensCount: [2, 2, 2, 2]  ← 每个专家处理2个token
```

**Step 4: 特征搬运**

根据 sortedRowIdx 重排特征数据：

```
sortedRowIdx: [1, 3, 0, 2, 1, 2, 0, 3]
                ↓ 搬运
expandedXOut: [x[1], x[3], x[0], x[2], x[1], x[2], x[0], x[3]]
```

## 2. 硬件架构基础

### 2.1 Ascend AI Core 架构概览

Ascend AI Core 采用独特的 DaVinci 架构，包含以下主要组件：

```
┌─────────────────────────────────────────────────────────────┐
│                        AI Core                               │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────────────┐ │
│  │   MTE1  │  │   MTE2  │  │   MTE3  │  │      Cube       │ │
│  │ (L1→UB) │  │ (GM→UB) │  │ (UB→GM) │  │   (矩阵计算)    │ │
│  └─────────┘  └─────────┘  └─────────┘  └─────────────────┘ │
│                                                              │
│  ┌─────────────────────────────────────────────────────────┐│
│  │                    Unified Buffer (UB)                   ││
│  │                      1.5 MB / AICore                     ││
│  └─────────────────────────────────────────────────────────┘│
│                          ▲                                   │
│                          │                                   │
│  ┌─────────────────────────────────────────────────────────┐│
│  │                    Vector Unit (Vector)                  ││
│  │      支持向量化计算：Sort、Reduce、Cast、Muls 等          ││
│  └─────────────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────────────┘
```

### 2.2 关键性能概念

#### 2.2.1 Roofline Model

对于 `MoeInitRoutingV3` 算子，其计算特性属于 **内存带宽受限 (Memory Bound)** 类型。

理论峰值带宽计算：
```
理论带宽 = AI Core 数量 × 单核峰值带宽
        = 1 × 51.2 GB/s (Atlas A2)
        = 51.2 GB/s
```

#### 2.2.2 内存层次与访问优化

| 存储类型 | 大小 | 带宽 | 延迟 |
|---------|------|------|------|
| GM (Global Memory) | 数十 GB | 51.2 GB/s | 高 |
| L2 Cache | 共享 | 高 | 中 |
| L1 Buffer | 1 MB | 极高 | 低 |
| UB (Unified Buffer) | 1.5 MB | 极高 | 极低 |

#### 2.2.3 向量化指令

Ascend C 提供丰富的向量化指令，对排序场景最关键的包括：

| 指令 | 功能 | 吞吐 |
|------|------|------|
| `Sort` | 向量排序 | 32 元素/指令 |
| `Concat` | 向量拼接 | 高吞吐 |
| `Extract` | 向量提取 | 高吞吐 |
| `Cast` | 类型转换 | 64 元素/指令 |
| `Muls` | 标量乘法 | 64 元素/指令 |

### 2.3 排序算法：VBS 和 VMS

Ascend C 提供两种排序模式：

#### VBS (Vector Based Sort)
- 单核排序，适用于小规模数据
- 使用 `Sort<T, true>` API
- 一次排序 32 个元素，需要 Concat 拼接

#### VMS (Merge Sort)
- 多核并行排序，适用于大规模数据
- 先分块排序，再归并
- 支持 2/3/4 路归并

## 3. 基准实现

### 3.1 代码展示

参见 [src/0_naive.cpp](src/0_naive.cpp)

### 3.2 实现原理

基准实现采用最直接的实现方式：

1. **排序阶段**: 使用单核 VBS 排序，将 expertIdx 和 rowIdx 一起排序
2. **直方图阶段**: 遍历排序后的 expertIdx，统计每个专家的 token 数量
3. **搬运阶段**: 根据 expandedRowIdx 逐行搬运特征数据

### 3.4 瓶颈分析

通过 Profiling 分析，主要瓶颈包括：

1. **GM 访问频繁**: 每次 CopyIn/CopyOut 都访问 GM
2. **排序效率低**: 单核处理全部数据，无法利用多核并行
3. **直方图计算串行**: 逐个元素遍历，未向量化
4. **搬运效率低**: 逐行搬运，未利用 Double Buffer

```
┌─────────────────────────────────────────────────────────────┐
│                    Naive 实现瓶颈图                          │
│                                                              │
│  GM ──────▶ [排序] ──────▶ [直方图] ──────▶ [搬运] ──────▶ GM │
│              │               │               │              │
│              ▼               ▼               ▼              │
│         单核串行        逐元素遍历       逐行搬运             │
│         效率低          未向量化         无流水              │
│                                                              │
│  瓶颈占比: 排序 40% | 直方图 30% | 搬运 30%                  │

```

## 5. 优化阶段二：多核并行排序

### 5.1 优化思路

当数据量较大时，单核排序成为瓶颈。多核并行排序策略：

1. **数据分块**: 将 N*K 个元素分配到多个 Core
2. **局部排序**: 每个 Core 对自己的数据块进行排序
3. **归并排序**: 使用 MrgSort 合并各 Core 的结果
