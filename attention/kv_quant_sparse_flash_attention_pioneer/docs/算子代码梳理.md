# KvQuantSparseFlashAttentionPioneer 算子代码梳理

## 1. 算子概述

### 1.1 功能定位

`KvQuantSparseFlashAttentionPioneer` 是面向 Ascend NPU 的**量化稀疏 Flash Attention** 算子，针对 MLA（Multi-Head Latent Attention）架构设计。在大模型长上下文推理场景中，该算子通过"只计算关键 KV 块"大幅减少计算量，同时支持 Per-Token-Head-Tile-128 量化输入，进一步降低访存带宽需求。

### 1.2 计算公式

$$
Attention = \text{softmax}\left(\frac{Q \cdot \text{Dequant}(\tilde{K}^{INT8}, Scale_K)^T}{\sqrt{d_k}}\right) \cdot \text{Dequant}(\tilde{V}^{INT8}, Scale_V)
$$

- $\tilde{K}, \tilde{V}$：基于选择算法（如 `LightningIndexer`）得到的高重要性 Key/Value，具有稀疏或分块稀疏特征
- $d_k$：Q/K 每个头的维度
- $\text{Dequant}(\cdot, \cdot)$：反量化函数（INT8/FP8 → FP32/BF16）

### 1.3 支持平台

| SoC | 架构目录 | KV 量化类型 |
|-----|---------|------------|
| ascend910b, kirinx90, kirin9030 | arch32 | INT8 |
| ascend910_93 | arch32 | INT8 |
| ascend950 | arch35 | FP8 (E4M3FN), HiFloat8 |

## 4. Host 侧逻辑

### 4.1 OpDef（*_def.cpp）

注册算子接口，声明 11 个输入、1 个输出、12 个属性，并为不同 SoC 配置数据类型约束：
- **ascend910b/910_93**：Q=FP16/BF16, K/V=INT8, Out=FP16/BF16
- **ascend950**：Q=BF16, K/V=FP8_E4M3FN/HiFloat8, Out=BF16

启用 DynamicCompile、DynamicFormat、DynamicRank、DynamicShape 支持。

### 4.2 InferShape（*_infershape.cpp）

输出 shape 推导逻辑：
```
BSND: output_shape = [B, S1, N, D - rope_head_dim]   // [B, S1, N, 576-64=512]
TND:  output_shape = [T, N, D - rope_head_dim]        // [T, N, 576-64=512]
```
输出数据类型与 query 保持一致。

### 4.3 Tiling 策略（*_tiling.h / *_tiling.cpp）

Tiling 是 Host 侧最核心的逻辑，负责将工作划分到多个 AI Core 上执行。

#### 4.3.1 Tiling 主流程

```
DoOpTiling()
  ├── GetPlatformInfo()      ← 获取 AIC/AIV 核数、L2 缓存大小
  ├── InitParams()           ← 设为 V_TEMPLATE_MODE，初始化核数
  ├── Split()                ← 执行切分策略
  │   └── SplitBalanced()    ← 均衡切分
  │       ├── CalcInnerSize()  ← 计算 S2 方向的 tile 大小
  │       └── CalcUbBmm()      ← 计算 UB 中 BMM 结果的 buffer 大小
  ├── FillTiling()           ← 填充 TilingData 结构体
  ├── CalcBlockDim()         ← 计算 kernel launch 的 block 维度
  ├── GetWorkspaceSize()     ← 计算所需 workspace 总大小
  └── GenTilingKey()         ← 生成 tiling key 用于 kernel 模板选择
```

#### 4.3.2 关键切分参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| mBaseSize | 128 | M 维度（S1×G）的基础 tile 大小 |
| s2BaseSize (sInnerSize) | 512 | S2 方向的 tile 大小（可降至 256/128） |
| usedCoreNum | = aicNum | 使用全部 AIC 核 |
| BUFFER_NUM | 2 | 双缓冲流水 |

#### 4.3.3 TilingData 结构体

```cpp
KvQuantSparseFlashAttentionPioneerTilingDataMla
├── BaseParams         // batchSize, seqSize(S2), qSeqSize(S1), blockSize,
│                      // scaleValue, sparseMode, sparseBlockSize/Count, dSizeVInput
├── SplitKVParams      // s2(KV 切分数), accumOutSize, logSumExpSize
├── SingleCoreParams   // usedCoreNum
├── SingleCoreTensorSize // mmResUbSize, bmm2ResUbSize
└── InnerSplitParams   // mBaseSize, s2BaseSize
```

#### 4.3.4 Workspace 组成

```
workspace = LibAPI 空间
           + BMM1 结果 (preLoadNum × mmResUbSize × coreNum × 4B)
           + Vec1 结果 (preLoadNum × mmResUbSize × coreNum × 2B)
           + BMM2 结果 (preLoadNum × bmm2ResUbSize × coreNum × 4B)
           + Softmax sum (preLoadNum × mBaseSize × coreNum × 4B)
           + Vec2 结果 (preLoadNum × bmm2ResUbSize × coreNum × 4B)
           + 稀疏聚合缓冲 (4 × 512 × 576 × 2 × coreNum)
           + MTE2 缓存 (4 × 128 × 4 × 2 × coreNum)
           + [Flash Decode workspace]
```

#### 4.3.5 参数校验（QSFAPTilingCheck）

- 数据类型合法性（Q=FP16/BF16, K/V=INT8/FP8, sparse_indices=INT32）
- 布局一致性（非 PA 场景 Q 和 KV 布局须一致）
- 维度匹配（Q_N 须为 1/2/4/.../128，KV_N 仅支持 1）
- sparse_block_size 须在 [1,16] 且为 2 的幂
- sparse_mode 仅支持 0 或 3
- PA 模式须提供 block_table 和 actual_seq_lengths_kv

## 5. Kernel 侧逻辑

### 5.1 整体架构：AIC/AIV 异构协同

该算子采用 **AIC（AI Cube）+ AIV（AI Vector）** 异构并行执行模式：

```
┌──────────────────────────────────────────────────────────────┐
│                    NPU AI Core                               │
│                                                              │
│  ┌──────────────┐          ┌──────────────┐                  │
│  │  AIC (Cube)  │          │  AIV (Vector) │                 │
│  │              │  SSBuf   │               │                 │
│  │  QSFAMatmul  │◄────────►│ QSFAVector    │                 │
│  │  Service     │  同步通道 │ Service       │                 │
│  │              │          │               │                 │
│  │  BMM1: Q@K^T │          │ Vec0: 加载KV  │                 │
│  │  BMM2: P@V   │          │ Vec1: Softmax │                 │
│  │              │          │ Vec2: 输出写回 │                 │
│  └──────────────┘          └──────────────┘                  │
│         │                          │                         │
│         ▼                          ▼                         │
│  ┌─────────────────────────────────────────┐                 │
│  │    L1 Buffer (512KB) / L0A/L0B/L0C      │                 │
│  └─────────────────────────────────────────┘                 │
│                        │                                     │
│                        ▼                                     │
│  ┌─────────────────────────────────────────┐                 │
│  │          Global Memory (GM/HBM)         │                 │
│  └─────────────────────────────────────────┘                 │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 Kernel 入口（*.cpp）

```cpp
__global__ __aicore__ void kv_quant_sparse_flash_attention_pioneer<
    FLASH_DECODE, LAYOUT_T, KV_LAYOUT_T, TEMPLATE_MODE>(
    query, key, value, sparseIndices, keyScale, valueScale,
    blocktable, actualSeqLengthsQ, actualSeqLengthsKV,
    key_sink, value_sink, attentionOut, workspace, tiling)
```

**模板参数**：
- `FLASH_DECODE`：0=正常模式，1=单 query decode 模式
- `LAYOUT_T`：0=BSND，1=TND
- `KV_LAYOUT_T`：0=BSND，1=TND，2=PA_BSND
- `TEMPLATE_MODE`：0=C_TEMPLATE，1=V_TEMPLATE

**数据类型组合**：
| 组合 | Q_T | KV_T | 中间类型 T | OUTPUT_T |
|------|-----|------|-----------|----------|
| 1 | bfloat16 | fp8_e4m3fn | float32 | bfloat16 |
| 2 | bfloat16 | hifloat8 | float32 | bfloat16 |

根据核类型实例化不同服务类：
- **AIC 核**：`CubeBlockType = QSFAMatmulService`，`VecBlockType = QSFAVectorServiceDummy`
- **AIV 核**：`CubeBlockType = QSFAMatmulServiceDummy`，`VecBlockType = QSFAVectorService`

### 5.3 主 Kernel 类（*_kernel_mla.h）

类名：`KvQuantSparseFlashAttentionMla<CubeBlockType, VecBlockType>`

#### 5.3.1 内存层级与 Buffer 布局

```
┌─────────────────── Global Memory (GM) ───────────────────────┐
│  query / key / value / sparseIndices / blockTable            │
│  actualSeqLengthsQ / actualSeqLengthsKV / attentionOut       │
│  workspace                                                    │
└──────────────────────────────────────────────────────────────┘
                          ↕ DataCopy (MTE2/MTE3)
┌─────────────────── L1 Buffer (512KB) ────────────────────────┐
│  l1QBuffers       : Query 缓存                                │
│  l1RightBuffers   : KV 数据（三缓冲）                          │
│  mm1ResultBuf     : 16KB (32×128×4B)                          │
│  mm2ResultBuf     : 64KB (32×512×4B)                          │
│  mm1RightBuf      : 147KB (128×576×2B)                        │
└──────────────────────────────────────────────────────────────┘
                          ↕
┌─────────────────── L0A/L0B/L0C ──────────────────────────────┐
│  L0A : 64KB → 2×32KB 双缓冲 (左矩阵)                          │
│  L0B : 64KB → 2×32KB 双缓冲 (右矩阵)                          │
│  L0C : 256KB → 2×128KB 双缓冲 (Cube 累加器)                    │
└──────────────────────────────────────────────────────────────┘
                          ↕
┌─────────────────── Unified Buffer (UB) ──────────────────────┐
│  bmm1Buffers      : BMM1 结果（双缓冲，核间同步）               │
│  bmm2Buffers      : BMM2 结果（单缓冲，核间同步）               │
│  softmaxMaxBuf[2] : Softmax max 统计量                        │
│  softmaxSumBuf[2] : Softmax sum 统计量                        │
│  softmaxExpBuf[2] : Softmax exp 中间结果                       │
│  commonTBuf       : 共享工作缓冲                               │
│  dequantScaleBuff : 反量化 Scale 缓冲                          │
└──────────────────────────────────────────────────────────────┘
```

#### 5.3.2 初始化流程

```
Init()
  ├── 1. 检测核类型（AIC / AIV / 混合）
  ├── 2. 获取 BlockIdx 和 SubBlockIdx
  ├── 3. 设置基础尺寸：s1BaseSize=64, s2BaseSize=128
  ├── 4. 初始化 VecBlock（AIV 核的向量服务）
  ├── 5. 核间同步 CrossCoreWaitFlag<SYNC_MODE>(15)
  ├── 6. 从 SSBuf 拷贝共享参数：CVSharedParams
  ├── 7. ComputeConstexpr()：预计算维度/步长常量
  ├── 8. InitGlobalBuffer()：设置 GM GlobalTensor 视图
  ├── 9. InitCalcParamsEach()：计算每核的工作分配
  │   ├── 统计全部 batch 的 base block 总数
  │   ├── 均衡分配到各核：bN2Start/End, gS1Start/End
  │   └── 处理核数 > 块数的空闲核情况
  └── 10. InitLocalBuffer()：分配 L0/L1/UB buffer
      └── InitMMResBuf()：分配 L1 矩阵乘结果 buffer
```

#### 5.3.3 主循环（ProcessMainLoop）

这是算子的核心执行逻辑，采用**三级流水**编排：

```
ProcessMainLoop()
  for each (Batch-N2 索引 bN2Idx):
    ComputeParamBatch()       ← 计算当前 batch 的参数
    ComputeS1LoopInfo()       ← 计算 S1 方向循环边界

    for each (GS1 索引):
      ComputeSouterParam()    ← 计算子块划分
      ComputeS2LoopInfo()     ← 计算 S2 方向（稀疏 KV）循环边界

      for each (S2 索引, taskId = 0,1,2,...):
        runInfoIdx = taskId % 3    ← 三缓冲轮转

        ┌────────── 三级流水编排 ──────────┐
        │                                   │
        │  Stage 0 (当前 taskId):            │
        │    AIC: cubeBlock.IterateBmm1()   │  ← Q @ K^T
        │    AIV: vecBlock.ProcessVec0()    │  ← 加载KV + 反量化
        │                                   │
        │  Stage 1 (taskId-1, 若 taskId>0): │
        │    AIC: cubeBlock.IterateBmm2()   │  ← P @ V
        │    AIV: vecBlock.ProcessVec1()    │  ← Softmax + Cast
        │                                   │
        │  Stage 2 (taskId-2, 若 taskId>1): │
        │    AIV: vecBlock.ProcessVec2()    │  ← 归一化 + 写回 GM
        │                                   │
        └───────────────────────────────────┘
```

**流水示意**（时间轴向右）：

```
时间 →    T0          T1          T2          T3          T4
AIC:   BMM1[0]     BMM1[1]     BMM1[2]     BMM1[3]     ...
                   BMM2[0]     BMM2[1]     BMM2[2]     ...
AIV:   Vec0[0]     Vec0[1]     Vec0[2]     Vec0[3]     ...
                   Vec1[0]     Vec1[1]     Vec1[2]     ...
                               Vec2[0]     Vec2[1]     ...
```

三级流水使得数据加载、计算、输出写回三个阶段并行，实现持续吞吐。

### 5.4 Cube 服务（*_service_cube_mla.h）

类名：`QSFAMatmulService`，运行在 AIC（Cube/矩阵加速引擎）核上。

#### 5.4.1 核心常量

```cpp
s1BaseSize = 64       // Q 方向 tile 行数
s2BaseSize = 128      // KV 方向 tile 列数
dBaseSize = 576       // K/V 隐藏维度（含 rope + nope + scale）
dBaseMatmulSize = 128 // Matmul 的约化维度
```

#### 5.4.2 Buffer 分配

| Buffer | 位置 | 大小 | 用途 |
|--------|------|------|------|
| l1QBuffers | L1 | 单缓冲 | Query 矩阵缓存 |
| l1KBuffers | L1 | 三缓冲 | Key 矩阵（流水） |
| mmL0ABuffers | L0A | 3×16KB | 左矩阵 |
| mmL0BBuffers | L0B | 3×32KB | 右矩阵 |
| mmL0CBuffers | L0C | 3×128KB | Cube 累加器 |

#### 5.4.3 核心方法

**`IterateBmm1()`**：计算 $Q \times K^T$（注意力分数）
- 输入：UB 中的输出 buffer + L1 中的 K 数据
- 流程：L1→L0B 拷贝 → L0A×L0B Matmul → L0C→UB 拷贝

**`IterateBmm2()`**：计算 $P \times V$（注意力输出）
- 输入：Softmax 后的注意力权重 P + L1 中的 V 数据
- 流程：与 BMM1 类似但维度不同

### 5.5 Vector 服务（*_service_vector_mla.h）

类名：`QSFAVectorService`，运行在 AIV（向量计算引擎）核上。

#### 5.5.1 核心常量

```cpp
s1BaseSize = 64         // 行 tile 大小
s2BaseSize = 128        // 列 tile 大小
vec1Srcstride = 65      // (s1BaseSize >> 1) + 1
dVTemplateType = 512    // 向量隐藏维度（输出）
dVTemplateTypeInput = 672  // 输入隐藏维度（含 RoPE + padding）
```

#### 5.5.2 三阶段处理

**ProcessVec0（Stage 0）：加载 KV + 反量化**

```
ProcessVec0(l1OutputBuf, runInfo, constInfo)
  ├── 1. 从 GM 读取 sparse_indices 获取稀疏块索引
  ├── 2. GetRealCmpS2Idx()：将稀疏块索引映射为实际 KV token 位置
  ├── 3. GetkeyOffset()：计算 KV 实际 GM 偏移（处理 PageAttention 块表间接寻址）
  ├── 4. CopyInKvSparse()：从 GM 加载稀疏 KV 数据到 UB
  │   ├── 验证 token 索引有效性
  │   ├── 支持缺失 token 处理（返回实际加载数）
  │   └── 使用 DataCopy 搬运
  └── 5. 反量化：INT8/FP8 → float（使用 per-tile scale）
      └── 将反量化后的 KV 写入 L1 供 Cube 消费
```

**ProcessVec1（Stage 1）：Softmax 计算**

```
ProcessVec1(bmm1Result, runInfo, constInfo)
  ├── 1. 从 UB 读取 BMM1 结果（Q@K^T 注意力分数）
  ├── 2. 乘以 scale: P_scaled = P × softmax_scale
  ├── 3. 行方向求 max: max_row = reduce_max(P_scaled)
  ├── 4. 指数计算: exp_P = exp(P_scaled - max_row)
  ├── 5. 行方向求和: sum_exp = reduce_sum(exp_P)
  ├── 6. 根据是否为首次迭代：
  │   ├── 首次 (NoUpdate): 直接输出 exp_P、max、sum
  │   └── 非首次 (Update): 合并历史统计量
  │       ├── max_new = Max(max_cur, max_prev)
  │       └── sum_new = exp(max_prev - max_new) × sum_prev + sum_cur
  └── 7. Cast float32 → bfloat16，写入 UB
```

**ProcessVec2（Stage 2）：最终归一化 + 输出**

```
ProcessVec2(bmm2Result, runInfo, constInfo)
  ├── 1. 从 UB 读取 BMM2 结果（P @ V）
  ├── 2. 根据迭代位置：
  │   ├── 中间迭代: FlashUpdateNew()
  │   │   └── dst = pre × exp(max_new - max_old) + cur
  │   ├── 最后迭代: FlashUpdateLastNew()
  │   │   └── dst = (pre × exp(max_new - max_old) + cur) / sum_exp
  │   └── 仅一次迭代: LastDivNew()
  │       └── dst = cur / sum_exp
  ├── 3. Cast float32 → bfloat16
  └── 4. DataCopy 写回 GM 的 attentionOut
```

## 6. Softmax 微核函数（vf/ 目录）

### 6.1 调度路由（vf_mul_sel_softmaxflashv2_cast_nz_qsfa.h）

根据 S2 维度实际大小，编译期选择不同的优化路径：

```cpp
enum OriginNRange {
    EQ_128_QSFA,           // N == 128：对齐路径（最优）
    GT_0_AND_LTE_64_QSFA,  // 0 < N ≤ 64：小块路径
    GT_64_AND_LTE_128_QSFA // 64 < N ≤ 128：通用路径（需 padding）
};
```

结合是否需要状态更新（Update/NoUpdate），共产生 **6 条执行路径**：

```
ProcessVec1Vf()
  ├── isUpdate == false:
  │   ├── N == 128    → ProcessVec1NoUpdateImpl128()
  │   ├── N ≤ 64      → ProcessVec1NoUpdateImpl64()
  │   └── 64 < N ≤ 128 → ProcessVec1NoUpdateGeneralImpl128()
  └── isUpdate == true:
      ├── N == 128    → ProcessVec1UpdateImpl128()
      ├── N ≤ 64      → ProcessVec1UpdateImpl64()
      └── 64 < N ≤ 128 → ProcessVec1UpdateGeneralImpl128()
```

### 6.2 对齐 128 路径（vf_basic_block_aligned128_*.h）

最高效路径，N 恰好为 128 时使用。

**Phase 1：Scale & 求 Max**
```cpp
for each row i in [0, m):
    Load vreg[0:64], vreg[64:128]          // 加载 128 个 fp32
    Muls(vreg, vreg, scale)                 // 乘以 scale
    Max(vreg_max, vreg[0:64], vreg[64:128]) // 元素级取 max
    Reduce<MAX>(row_max, vreg_max)          // 规约得行最大值
```

**Phase 2：Exp & 求 Sum & Cast**
```cpp
for each row i in [0, m):
    BroadcastLoad(max_brc, row_max[i])     // 广播最大值
    DeinterleaveLoad(even, odd, src)        // 交错加载
    ExpSub(exp_even, even, max_brc)         // exp(x - max)
    ExpSub(exp_odd, odd, max_brc)
    Add(exp_sum, exp_even, exp_odd)         // 求和
    Reduce<SUM>(row_sum, exp_sum)           // 规约
    Cast<BF16>(bf16_even, exp_even)         // fp32 → bf16
    Cast<BF16>(bf16_odd, exp_odd)
    Or(bf16_packed, bf16_even, bf16_odd)    // 合并偶/奇 bf16
    Store(output, bf16_packed)
```

### 6.3 非对齐路径（vf_basic_block_unaligned*.h）

处理 N < 128 的尾部块，使用 **mask + minValue padding** 策略：

```cpp
// N ≤ 64：单寄存器处理
preg_mask = UpdateMask(originN)           // 创建有效元素掩码
Muls(vreg, vreg, scale, preg_mask)        // 仅 scale 有效元素
Reduce<MAX>(max, vreg, preg_mask)         // 仅对有效元素求 max
ExpSub(exp, vreg, max_brc, preg_mask)     // 仅对有效元素求 exp

// 64 < N ≤ 128：双寄存器处理 + padding
preg_tail_mask = UpdateMask(N - 64)       // 第二寄存器的有效掩码
Duplicate(vreg_min, FLOAT_MIN)            // 填充极小值
Select(vreg_tail, vreg_data, vreg_min, preg_tail_mask)  // 无效位用极小值
// 极小值经过 exp 后变为 ≈ 0，不影响 softmax 结果
```

### 6.4 Flash Update（vf_flashupdate_new_qsfa.h）

实现 Flash Attention 的迭代累积更新，确保数值稳定性：

| 函数 | 公式 | 场景 |
|------|------|------|
| `FlashUpdateNew()` | $dst = pre \times e^{max_{new} - max_{old}} + cur$ | 中间迭代 |
| `FlashUpdateLastNew()` | $dst = \frac{pre \times e^{max_{new} - max_{old}} + cur}{sum_{exp}}$ | 最后一次迭代 |
| `LastDivNew()` | $dst = \frac{cur}{sum_{exp}}$ | 仅单次迭代 |

### 6.5 统计量更新（QSFAUpdateExpSumAndExpMax）

每次处理新 KV 块后，更新全局 softmax 统计量：

```
max_new = Max(max_cur, max_prev)
exp_delta = exp(max_prev - max_new)
sum_new = exp_delta × sum_prev + sum_cur
```

## 9. 关键设计总结

| 设计要点 | 实现方式 |
|---------|---------|
| **稀疏注意力** | 通过 sparse_indices 索引仅加载/计算高重要性 KV 块，跳过无关数据 |
| **量化支持** | KV 以 INT8/FP8 存储，combine 模式下量化 scale 与数据混存（per-tile-128 量化） |
| **MLA 架构** | Query 含 rope+nope 两部分（576D），输出去除 rope（512D） |
| **异构并行** | AIC 核执行矩阵乘，AIV 核执行向量运算，通过 SSBuf 核间同步 |
| **三级流水** | 数据加载/计算/输出写回三阶段重叠，taskId%3 轮转 |
| **三缓冲 L1** | L1 中 KV 数据使用三缓冲，允许加载→计算→下一次加载并行 |
| **双缓冲 UB** | BMM1 结果在 UB 中双缓冲，支持 ping-pong 流水 |
| **Flash Attention 迭代** | 多 KV 块场景下通过 exp(max_delta) 缩放历史累积值，保证数值稳定性 |
| **Softmax 6 路径优化** | 根据 N 维度大小 + 是否需要状态更新，编译期选择最优微核实现 |
| **Mask + MinValue Padding** | 尾部不足 128 的块用极小值填充，softmax 后自动变为 ≈0 |
| **PageAttention** | 通过 block_table 间接寻址，支持分页 KV Cache 存储 |
| **多布局支持** | BSND（标准）、TND（Token 打包）、PA_BSND（分页）三种布局 |
| **32 字节对齐** | 所有 DMA 操作的 buffer 基地址严格 32 字节对齐 |
